## Technical Interview Assignment — "Magnific" Creative Pipeline

### The Product Idea

**Magnific** is a creative automation tool for artists and storytellers. A user uploads two character reference images and describes a creative idea (e.g., *"a loving couple going through daily life — arguments, chores, reconciliation"*). The system produces a set of short animated video clips featuring those exact characters.

The pipeline conceptually has three stages:

1. **Story & Prompt Generation** — A multimodal LLM (Google Gemini) looks at the reference images, reads the creative brief, and writes a structured list of scene prompts (titles + detailed image-generation prompts).
2. **Preview Generation** — For each scene prompt, an image-generation model produces a high-quality preview still, keeping character designs consistent with the reference images.
3. **Video Animation** — Each preview still is fed to a video-generation model (Google Veo) to produce a short cinematic MP4 clip.

Between stages, the system should write **manifest files** (JSON or YAML) so that stages can be run independently, retried, or resumed.

#### 2. Working Code (in a public GitHub repo)

Implement the pipeline. The repo must include:

- **`src/` or equivalent** — Clean module structure. If you identify shared logic (config loading, path resolution, retry logic), extract it into a shared module. Do not copy-paste boilerplate across agents.
- **Config-driven design** — All tunable parameters (model names, prompts, API rate limits, output paths, concurrency settings, retry policies) must live in external YAML/JSON/TOML files. The evaluator should be able to change the model, prompt, or aspect ratio without touching `.py` files.
- **Typed Python** — Type-hint all public functions and classes. Use `pathlib`, `dataclasses` or `Pydantic`, and modern Python patterns.
- **CLI entry points**:
  - `python -m magnific generate-config --idea "..."` (or similar) to create a job configuration
  - `python -m magnific run --config workflow.yaml` to run the full pipeline
  - `python -m magnific run --config workflow.yaml --from-stage preview` to resume/skip stages
  - `python -m magnific status --job-id <UUID>` to inspect a past or running job
- **Manifest chain** — JSON manifest files between stages so the pipeline is inspectable and resumable.
- **Job isolation** — Each run gets a unique job ID. Outputs for different jobs never overwrite each other.
- **Error resilience** — Retry transient API errors with exponential backoff. Handle safety-filter blocks without crashing the whole pipeline. Write partial results.
- **Tests** — At least one unit test per non-trivial module. Use `pytest`. You may mock the Google APIs; we will not run tests that require real API keys.

#### 3. Documentation
- **`README.md`** — Setup, dependencies, environment variables, how to run, how to test.
- **`ARCHITECTURE.md`** — From Part 1.
- **`CHANGELOG.md`** — Design decisions and trade-offs you made (e.g., why async vs sync, why SQLite vs JSONL, why Pydantic vs dicts).
- **Developer setup** — `requirements.txt` or `pyproject.toml` with pinned dependencies.

### Functional Requirements Checklist

We will evaluate your code against these behaviors:

- [ ] Can generate a valid workflow/config file from a text idea.
- [ ] Can execute stage 1 (story generation) independently and produce a JSON manifest.
- [ ] Can execute stage 2 (preview generation) using the stage 1 manifest + reference images, concurrently, with a configurable concurrency cap.
- [ ] Can execute stage 3 (video animation) using stage 2 manifest, with concurrent polling so wall time ≈ slowest video, not sum of all videos.
- [ ] Orchestrator can run all three stages end-to-end under a single job ID.
- [ ] Orchestrator supports resuming from a specific stage.
- [ ] All output paths, model identifiers, prompts, and runtime parameters are driven by external config.
- [ ] Graceful handling of API failures (rate limits, safety blocks, network errors).
- [ ] Partial failure produces usable artifacts and a clear log/manifest of what succeeded and what failed.
